#### Задание 1
##### Задача 10
Текст задачи: Измените сущности из задачи 1.3.3. Гарантируйте, что между двумя городами может быть только одна прямая дорога. Города можно создавать с указанием заранее заданных путей, в любой момент времени можно добавить новую дорогу и удалить имеющуюся.

Входные данные: Строки (названия городов), целые числа (стоимость пути), выбор пункта меню.

Выходные данные: Текстовое представление списка городов и их путей, сообщения об успешном добавлении/удалении или об ошибках.

Алгоритм решения: Класс City хранит список путей List<Path>. В методе addPath реализована проверка: перед добавлением перебирается текущий список путей, и если путь в указанный город уже существует (сравнение по имени), выбрасывается исключение IllegalArgumentException. Также запрещено добавлять путь в сам себя. Метод removePath ищет путь по имени города назначения и удаляет его через итератор/список. В Main реализовано консольное меню для интерактивного управления графом.

#### Задание 2
##### Задача 5
Текст задачи: Разработка сущности Маршрут на основе Города. Маршрут имеет начало и конец, может вернуть массив городов пути и строковое представление.

Входные данные: Объекты City (начало и конец маршрута).

Выходные данные: Массив City[] или строка с названиями городов.

Алгоритм решения: Создан класс Route с полями start и end. Сеттеры проверяют на null. Для поиска пути используется рекурсивный поиск в глубину (DFS) в методе findPath. Создается список path для накопления маршрута и множество visited для избежания циклов. Если город назначения достигнут, возвращается true и маршрут сохраняется. При тупике последний элемент удаляется из пути (бэктрекинг). Метод getRoute() возвращает массив, а toString() переопределен для красивого вывода последовательности городов через ->.

#### Задание 3
##### Задача 3
Текст задачи: Создайте подвид сущности Город, который гарантирует, что при добавлении дороги из одного города в другой одновременно добавляется и обратная дорога.

Входные данные: Названия городов, стоимость пути.

Выходные данные: Текстовое представление графа с двусторонними связями.

Алгоритм решения: Создан класс MutualCity, наследуемый от City. В нем переопределен метод addPath. Сначала вызывается super.addPath(...) для добавления прямой дороги, затем напрямую в список путей целевого города (other.getPaths()) добавляется новый объект Path, ведущий обратно в текущий город. Аналогично переопределен removePath для удаления обеих дорог.

Выходные данные: Текстовая строка вида {x; y; z}.

Полученный граф выводится на экран.

#### Задание 6
##### Задача 5
Текст задачи: Измените сущность Город. Переопределите метод сравнения, чтобы два Города считались одинаковыми при одинаковом наборе путей. Подвид (MutualCity) должен быть сравним с обычным городом.

Входные данные: Объекты City и MutualCity с различными путями.

Выходные данные: Логические значения (true/false) результатов сравнения.

Алгоритм решения: В классе City переопределены методы equals и hashCode. equals сравнивает списки путей this.paths.equals(other.paths). Для корректной работы в коллекциях hashCode вычисляется на основе хэша списка путей. Так как MutualCity наследует equals от City, сравнение происходит по тому же принципу (сравниваются наборы путей, независимо от того, как они были добавлены).

#### Задание 8
##### Задача 4
Текст задачи: Измените сущность Точка. Переопределите метод клонирования, унаследованный от Object, чтобы он возвращал новый объект с копиями значений полей.

Входные данные: Объект Point с заданными координатами.

Алгоритм решения: Класс Point реализует интерфейс Cloneable. Переопределен метод clone() с модификатором доступа public. Обрабатывается проверяемое исключение CloneNotSupportedException (выбрасывается AssertionError, так как класс реализует Cloneable). В Main создается точка, клонируется, проверяется неравенство ссылок (p1 == p2 -> false), и демонстрируется независимость изменения координат клона.
